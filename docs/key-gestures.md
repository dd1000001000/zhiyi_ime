# 快捷键的点按与长按

所有快捷键按同一种方式判断“按下、点按、长按”，再交给各自的功能。现在只有语音输入键在选了“长按”时有长按功能
（按住说话），其他快捷键的行为和以前一样。

## 包括哪些键

| 键 | 什么时候算快捷键 |
|----|------------------|
| 五个切换键的组合键（中英、输入方式、标点、全半角、语音输入）：F1–F11、Shift+Space、Ctrl / Alt 组合 | 设置了就算 |
| 单独轻按的 Shift / Ctrl / Alt（`ascii_composer.switch_key` 设了 `noop` 以外的值） | 设置了就算 |
| 翻页键 `-` `,` `[` / `=` `.` `]`（`shortcuts.page_up` / `page_down`） | 有候选时 |
| `/`（打开符号输入后再按一次出 `/`） | 打字时 |
| 学习模式的 Ctrl+0～9（打出翻译） | 打字时，且设了学习语言 |

Caps Lock 跟着指示灯切换、激活输入法的快捷键是系统热键，都不在这里。

## 点按和长按

- **按下**：组合键、翻页键、`/`、Ctrl+数字按下时就起作用，和以前一样；按住不放时系统自动重复：翻页键连续翻页，
  `/` 和以前一样连续触发。
- **点按**：在长按时长内松开。单独的 Shift / Ctrl / Alt 在松开时才知道是不是点按（中间按了别的键就是组合键，
  不算点按）。
- **长按**：按住超过长按时长（`shortcuts.hold_ms`，默认 400 毫秒，100–2000），中间没按别的键。只有有长按功能的
  快捷键才有长按；没有长按功能的单独修饰键按多久都算点按（和以前一样）。

## 按住一个快捷键时又按了别的键

- **按住的是 Shift / Ctrl / Alt**：按下的任何键都和它组成组合键（Ctrl+C、Ctrl+Space、Ctrl+Shift），所以当它没按过：
  已经开始的长按悄悄撤销（语音输入放弃这次录音，不提示），组合键照常起作用（Ctrl+Space 切换中英，Ctrl+C 交给程序复制）。
- **按住的是组合键、翻页键、`/` 或 Ctrl+数字**：按了另一个快捷键时，先当它松开（长按的结束，还没到长按时长的算点按），
  再开始另一个快捷键。另一个是单独轻按的修饰键时，松开那个修饰键、确定是点按时才这样。按了普通键不影响它。
- 被结束的快捷键在真正松开、再按下之前不再起作用。
- 输入框失去焦点时，所有按着的快捷键都结束（语音输入放弃录音）。

## 语音输入键

“设置 > 按键”里语音输入快捷键右边选“点按两次”或“长按”（`voice.key_mode`：`tap` / `hold`，默认 `tap`）：

| | 组合键（如 F9） | 单独轻按的修饰键（如右 Ctrl） |
|---|---|---|
| 点按两次 | 按一下开始说话，再按一下结束；停顿一会儿也自动结束（见下） | 点按开始说话，再点按一下结束；同样会自动结束 |
| 长按 | 按下就开始说话，松开结束并识别；按下不到长按时长就松开算误按，悄悄放弃 | 按住到长按时长才开始说话，松开结束并识别；点按什么也不做 |

- 长按时按了另一个切换键：先当语音键松开（结束并识别），再切换。长按修饰键录音时按了别的键（如 Ctrl+C），这次录音悄悄放弃。
- 点按两次时，说完停顿 `voice.auto_stop_ms`（默认 2000 毫秒，只在配置文件里改，0 为不自动结束，500–10000）
  没有人声，录音自动结束，识别出的文字直接上屏（不带下划线）；还没开口时至少等 5 秒。长按时只由松开结束。

## 实现

- `shared/include/cxxime/key_gesture.h`（`KeyGestureTracker`）：纯逻辑，输入按键的按下、松开（含自动重复）、时间和
  “这个键还按着吗”，输出按下、自动重复、点按、长按开始、长按结束（松开 / 被另一个快捷键结束 / 失去焦点）和撤销。
- 输入法组件（`tsf/src/text_service_gesture.cpp`）把四个入口的按键都交给它：按键事件、系统登记的快捷键
  （`OnPreservedKey`）、被 Windows 系统热键拿走的键（`_run_held_switch_key`）和学习模式翻译键的键盘钩子；有快捷键
  按着时每 30 毫秒检查一次长按，并用 `GetAsyncKeyState` 补上收不到的松开（系统热键那条路收不到）。
- 语音输入键由输入法组件读：按键本身不再交给引擎，而是发 `kVoiceKeyPress` / `kVoiceKeyRelease` / `kVoiceKeyCancel`
  （`key_event.h`，Windows 未分配的键码）。这样的会话带 `kClientCapabilityVoiceKey`，引擎不再自己认语音快捷键和
  `toggle_voice`；没有这个标记的会话（还在用旧输入法组件的程序）照旧由引擎处理。
- 录音期间其他四个切换键的组合键仍然起作用，其余按键照旧被吃掉。
- 其他快捷键的按键照旧交给引擎处理。
