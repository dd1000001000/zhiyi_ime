# 学习模式（候选翻译）

学习模式在候选窗口里给每个候选词显示它在另一种语言里的意思和词性，打字时顺便学外语：

- **中文输入**：中文候选 → 英语、日语、韩语、法语、德语、西班牙语、俄语，七选一；
- **英文输入**：英文候选 → 中文、日语、韩语、法语、德语、西班牙语、俄语，七选一。

翻译来自预先生成的词表（语言包），输入法运行时只查表，不加载翻译模型，也不联网。

## 设置

设置里新增“学习”页（导航在“词库”之后），分成上下两块：上面选择翻译，下面管理语言包。
“常规”页只加一个“候选排列”。

### “常规”页：候选排列

| 设置项 | 取值 | 默认 |
|------|------|------|
| 候选排列 | 竖排 / 横排 | 竖排 |

选项下方提示“横排时不显示翻译”。翻译只画在竖排的候选窗口里，横排照旧。

### “学习”页：候选翻译

| 设置项 | 取值 | 默认 |
|------|------|------|
| 中文候选翻译 | 关 / 英、日、韩、法、德、西、俄 | 关 |
| 英文候选翻译 | 关 / 中、日、韩、法、德、西、俄 | 关 |

- 两个下拉框只能选已安装语言包的语言：没有安装的语言显示为灰色、后面标“（未下载）”，点了也选不上。
- 两项任意一项打开就是“学习模式”：设置程序同时把“候选排列”改成竖排（写入 `style.layout`）。
  关闭学习模式时不改回横排；候选窗口不对学习模式做特殊处理。
- 正在使用的语言包被删除时，对应的翻译自动改回“关”。

### “学习”页：语言包

- 列表分“中文 → 外语”“英文 → 外语”两组，每组 7 行。每行左边是语言名（中文名加本族语写法，如“日语 日本語”），
  下面一行小字是状态；右边是按钮：

  | 状态 | 小字 | 按钮 |
  |------|------|------|
  | 未下载 | `未下载 · 约 1.3 MB` | 下载 |
  | 下载中 | 进度条 + `正在下载 0.8 / 1.3 MB` | 取消 |
  | 已安装 | `v1 · 1.3 MB · 1.5 万词` | 检查更新、卸载 |
  | 检查后已是最新 | `… · 已是最新` | 检查更新、卸载 |
  | 检查后有新版本 | `… · 有新版本 v2` | 更新到 v2、卸载 |

- 标题右侧有“全部检查更新”，一次检查所有已安装的包；打开设置时如果勾选了“有新版本时提醒我”，也会顺便检查。
- 默认安装中→英、英→中两个包；所有包都能卸载。卸载的内置包再点“下载”时直接从安装目录恢复，不用联网
  （服务器上有更新的版本时下载新版本）。
- 下载或卸载完成后，上面两个下拉框里的可选语言随之更新。

“候选翻译”一块右侧有一个候选窗口预览，按当前选择的语言显示示例（中文 `xianzai`、英文 `develop`），
用和候选窗口相同的字体、颜色和 80% 字号的翻译列。

对应的配置项（`%USERPROFILE%\zhiyi\` 下的用户配置）：

| 配置项 | 说明 |
|------|------|
| `style.layout` | `vertical`（默认）或 `horizontal`；打开学习模式时设置程序改为 `vertical` |
| `learning.chinese_target` | 空（关闭）或 `en` `ja` `ko` `fr` `de` `es` `ru` |
| `learning.english_target` | 空（关闭）或 `zh` `ja` `ko` `fr` `de` `es` `ru` |

## 候选窗口

学习模式下每一行候选都显示翻译：

```
 xianzai
 1. 现在   n. now · adv. at present
 2. 显在   adj. apparent
 3. 线在
 4. 鲜在
```

```
 develop
 1. develop      v. 发展 · v. 开发
 2. developer    n. 开发者
 3. development  n. 发展 · n. 开发
```

- 一行最多三个常用义项，每个义项是“英文词性标签 + 译文”，义项之间用 ` · ` 分隔，按常用程度排列。
  两个义项在某种语言里译文相同时也分别显示（日语 `v. 発展する · n. 発展`、`n. 研究 · v. 研究`），暂不合并。
- 翻译列在候选文字之后对齐（同一页里候选最宽的那一列之后），字号是候选字号的 80%（14 号候选配 11 号），
  颜色用注释色（`comment_text_color`）；高亮行跟随高亮文字颜色。
- 太长时在行尾截断成“…”，从第三个义项开始舍弃，窗口宽度不超过现有的上限（工作区宽度的 80%，最多 960 DIP）。
- 没有翻译的候选（整句、组出来的长句、符号、表情、词表里没有的词）那一行只显示候选本身。
- 模糊音提示（`中国(zhong guo)`）和五笔剩余码照常显示在候选后面，翻译列在它们之后。
- Laya 推荐标记照常画在候选文字右上角。

### 词性标签

标签固定用英文缩写，不随界面语言变化：

| 词类 | 标签 | 词类 | 标签 |
|------|------|------|------|
| 名词 | `n.` | 介词 | `prep.` |
| 动词 | `v.` | 连词 | `conj.` |
| 形容词 | `adj.` | 助词 | `part.` |
| 副词 | `adv.` | 叹词 | `int.` |
| 代词 | `pron.` | 拟声词 | `onom.` |
| 数词 | `num.` | 量词 | `mw.` |
| 冠词/限定词（英文） | `det.` | 成语、习用语 | 不标 |

## 查表规则

- 中文候选按“词 + 拼音音节”查，同一个词的不同读音分别有翻译（行 xíng / háng，长 cháng / zhǎng）；
  按读音查不到时退回按词查，取最常用的读音。
- 英文候选按小写原词查（`Develop`、`DEVELOP` 都查 `develop`）；屈折形式单独成条，译文给原形的意思（went → 去）。
- 只查当前页的候选（最多 9 个），查表在 `zhiyi-server` 里完成，结果随候选页一起发给候选窗口。
- 自学习排序、Laya 重排、候选顺序都不受学习模式影响。

## 语言包

一共 14 个，每个方向、每种目标语言一个：

| 方向 | 包 | 词条（第 2 版） | 大小 |
|------|------|------|------|
| 中文 → 其他 | `zh-en` `zh-ja` `zh-ko` `zh-fr` `zh-de` `zh-es` `zh-ru` | 按词频排前 5 万的“词 + 读音”（含常用单字），约 4.1 万条有翻译 | 每个约 1.7 MB |
| 英文 → 其他 | `en-zh` `en-ja` `en-ko` `en-fr` `en-de` `en-es` `en-ru` | 英文词表中的普通单词，约 2.1 万条有翻译 | 每个约 0.6 MB |

第 1 版（1.1.0 自带）只收前 2 万个中文词和 8000 个英文词；第 2 版扩大到上表的范围（1.1.1 起自带）。
不成词的片段、没有通用简称的超长机构名、各语言写法相同的品牌名不收录。

- 输入法只从 `%USERPROFILE%\zhiyi\glossary\` 加载语言包。
- 安装包内置 `zh-en` 和 `en-zh`，放在安装目录的 `data\glossary\`。设置程序第一次启动时把它们复制到用户目录
  （用户目录里已有、或用户删除过的不复制；删除记录在 `glossary\state.json`），所以所有包的删除和更新都一样处理；
  安装的新版本内置包比用户目录里的新时同样复制过去。
- 不成词的片段（如“好像在”“与科技”）不收录。

### 文件格式

`<方向>-<目标>.gloss`，小端二进制，`zhiyi-server` 内存映射后只读访问：

```
头部
  magic           "ZYGLOSS\0"
  format_version  u16   文件结构版本，结构变化才加一；不认识的版本不加载
  content_version u32   这个包的翻译内容版本，翻译改动就加一
  source, target  各 8 字节语言代码（zh / en / ja …）
  entry_count     u32
  built           u32   生成日期（yyyymmdd）
  dict_sha256     32 字节，生成时所用拼音或英文词表的指纹（只用于追查）
索引   entry_count 个 {key_offset u32, value_offset u32}，按 key 的字节序排序（二分查找）
key    "词\t音节"（中文，音节用 : 分隔）或小写英文词，UTF-8，以 \0 结尾
value  1–3 个义项：{词性 u8, 译文 UTF-8 \0}，以词性 0xFF 结尾
```

### 版本

- 每个包有自己的内容版本，只修改了某一个包时只有那一个包升版，用户只重新下载这一个。
- 格式版本保证旧版输入法遇到新格式时跳过不加载，不会出错。
- 服务器上的清单可以给某个包标“最低软件版本”，旧版输入法不会去下载它用不了的包。

## 离线翻译

语言包只收常用词。词表里没有的候选（词组、生僻词、短句、新词）可以用下载到本机的翻译模型翻译：

- **模型**：腾讯 [Hy-MT2-1.8B](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF) 的 Q4_K_M 量化版（1.13 GB，Apache-2.0），
  由 llama.cpp 的 `llama-server.exe`（Vulkan 版，MIT）在显卡上运行。两者都不在安装包里，在“学习”页点“下载”时从本仓库的
  `translator` 发布下载（签名清单 `translator.json` + 模型 + 运行库压缩包，校验签名和 SHA-256），放在本机数据目录的
  `translator\v<版本>\`（`shared/include/cxxime/translator_files.h`）。
- **只用显卡**：只有显存大于 2 GB 的独立显卡才能打开，在“学习”页选用哪块显卡；约占 1.5 GB 显存。不支持 CPU 运行。
- **什么时候翻**：学习模式打开、竖排、这一项打开时，每页里语言包查不到、含文字、不超过 32 个字的候选
  （通常 3–7 个）交给模型，一页的几个词同时翻译（模型服务有 10 个并行通道，RTX 5070 Ti 上一页约 50–150 ms）。
  候选窗口先照常显示，翻译好了再补到这一页上；打字很快时只翻最新的一页。模型的译文没有词性，只显示译文；
  和原文一样的（如“yyds”）不显示。
- **上文**：光标前最多 32 个字（`learning.translator_context_chars`）随词一起交给模型，帮助多义词选对意思；
  比推荐模型用的上文短，翻得快。
- **加载与卸载**：第一次需要翻译时由 `zhiyi-server` 启动模型服务（约 3 秒，包括让显卡预先编译计算程序），
  60 秒（`learning.translator_idle_seconds`）没有要翻的词就关闭，释放显存。学习模式或这一项关闭时不会加载。
  模型服务只监听 127.0.0.1 的随机端口，用随机密钥访问，随 `zhiyi-server` 一起退出。
- **缓存**：翻过的词记在 `zhiyi-server` 的内存里（最多 2 万条），翻页回来不用重翻；不写入文件。
- 实现：`engine/src/machine_translation.cc`（启动模型服务、按显卡名称找到 Vulkan 设备、并行请求），
  `server/src/machine_translator.cc`（后台线程、缓存、空闲卸载），`settings/editor_translator.cc`（下载、试翻）。

## 下载与更新

语言包放在 GitHub 上单独的 Release（tag `glossary`，不标记为 latest，不影响软件更新）：

```
glossary.json          清单：每个包的 id、source、target、version、format、min_app、文件名、大小、SHA-256、词条数
glossary.json.sig      清单签名（与软件更新相同的 ECDSA P-256 密钥）
zh-ja.v1.gloss         文件名带内容版本；发布新版时只上传新文件，旧版本保留在 Release 里
…
```

- 只有设置程序联网：打开设置（勾选了“有新版本时提醒我”）、点“检查更新”或“全部检查更新”时下载清单，
  校验签名后和本地版本比较，有新版本的包显示“有新版本”。
- 下载先写成 `.part` 文件（可续传），校验大小和 SHA-256 后才替换旧文件；中途失败不影响正在用的包。
  旧文件可能正被 `zhiyi-server` 映射，替换前先把它改名移开。
- `zhiyi-server` 每隔至少 2 秒检查一次正在用的包文件，装上、更新或卸载后自动换用，不用重启输入法。
- 要回退时把清单指回 Release 里保留的旧文件即可。
- 输入法本身（TSF 模块和 `zhiyi-server`）仍然不联网，[隐私说明](privacy.md)不变。

## 词表的生成、改进与授权

- 词条取自知意输入法的拼音词典（按词频排前 2 万的“词 + 读音”）和英文词表；不改动词典本身。
- 翻译和词性由大语言模型离线生成（GLM-5.3-flash 为主，Gemma 4 26B 补充），一次给出 1–3 个常用义项，
  再经过自动检查（每种语言的文字系统、串列、长度、模型的附带说明等），有问题的词重新生成。
- 词表以文本形式公开在 [zhiyi-glossary](https://github.com/dd1000001000/zhiyi-glossary)：`base/` 是生成的底稿，
  `corrections/` 是人工修订（打包时覆盖底稿，重新生成也保留）。任何人都可以提“翻译纠错” Issue 或修改
  `corrections/` 提 Pull Request，每个 PR 自动检查格式，懂这门语言的审核人同意后合并；维护者用
  `tools/build.py` 生成语言包（只有内容变了的包升版本），签名后发布到 `glossary` Release。
- 词条来自 rime-ice 词库（GPL-3.0-only），词表和语言包按 GPL-3.0-only 发布。
- 生成脚本、提示词和中间数据不公开。
