# 联想（打完一个词后的下一个词）

提交一个词后，知意输入法在光标处列出接下来最可能打的词。设置 > 常规 >“上文推荐”下的“打完一个词后显示联想”（`laya.next_words`，默认开）。

## 什么时候出现

- 中文模式：选了一个候选（空格、数字键或鼠标）之后。原样打出的拼音、标点、数字、回车不会带出联想。
- 英文模式（单词联想）：打完一个单词、后面跟着空格之后（空格提交，或数字键选补全）。逐字母输入时不出现。
- 选了一个联想词之后，接着联想下一个；用 Ctrl+数字打出联想词的译文之后也一样。

## 怎么选

| 按键 | 作用 |
| --- | --- |
| 主键盘 1–9、0 | 打出第 1–10 个联想词（英文后面自动加空格，与 `engine.auto_space` 相同），然后接着联想 |
| Ctrl+1–9、0 | 学习模式下打出这个联想词的译文（勾了“数字键直接打出翻译”时与上一行互换） |
| 小键盘数字 | 照常打数字，联想关闭（“第1名”这类汉字后面紧跟数字的输入用小键盘打） |
| Esc | 关闭联想 |
| 其他键 | 关闭联想，再照常处理这个键（打字母就开始新的拼音） |
| 鼠标点联想词 | 打出这个词 |

单按 Ctrl、Shift 不会关闭联想；切换中英文会关闭。

## 联想词从哪里来

模型是知意 ml-flash-next-preview-1114：ML-Flash-1103 的选词和组句，加一个 4 层的续写解码器，两者共用一张 ONNX 图（`laya.one.next.slim.onnx`，64 MB）和同一个词表（`next_rows.json` 记着每一行的文字和每种语言能写哪些行）。选词时上文已经算过一次，联想直接用这份缓存，再做一次束搜索：

- 中文：解码器给出一页词，加上词语 n-gram ng1017 推荐的前 10 个词（由解码器打分），按 ln P_模型 + 0.75 × ln P_n-gram 排序。
- 英文：只用解码器。
- 最多“每页候选数”个词；模型概率低于 1% 的词不显示（中文时 n-gram 自己推荐的词保留），所以一页可能少几个。

预测在提交后的后台线程里算，不耽误打字：CPU 4 线程上中文约 26 ms（90% 在 36 ms 以内）、英文约 14 ms。算好之前又按了键，这次的结果就丢掉。

测试集（每种语言 1000 行，提交后真正打的下一个词）：中文第一个就是它 12.1%、一页里有它 29.0%，平均一页 8.9 个词；英文 18.3% / 46.8%，平均 8.9 个词。

## 学习模式

联想词和普通候选一样显示译文（语言包里没有的由离线翻译模型翻译）。翻译模型 V5 起，译文接着上文写：打完“我今天很”联想出“想你”，译文是“miss you”，而不是单独一句“I miss you.”。

## 设置项

见[设置说明](settings-guide.md)：`laya.next_words`、`laya.next_min_probability`、`laya.next_ngram_weight`、`laya.next_ngram_pool`、`laya.next_beam`。

## 实现

- 模型与搜索：`engine/src/laya/reranker.h`（一图的 `next_context` / `next_step`）、`engine/src/laya/next_words.h`（束搜索、n-gram 混排、阈值），`engine/src/laya/ngram.h`（`Ngram::next_words`）。
- 服务端：`server/src/session_manager.cc`（提交后请求联想、数字选词、Esc 和其他键关闭），`server/src/next_words_worker.h`（后台线程）。算好后像长拼音组句一样通知客户端重新取候选（`UiCommandType::kRefreshCandidates`）。
- 客户端：声明 `kClientCapabilityNextWords` 的 TSF 才会收到联想；回包的 `predicting` 为 1 时，候选窗在光标处显示、没有组字（`TextService::_show_next_words`）。更新后还在用旧版 DLL 的程序不会收到联想，按键照旧。
