# 隐私说明：用户体验改进计划

[English](privacy.en.md)

知意输入法的用户体验改进计划分两档，**默认都不开启**，只有你在安装程序或“设置 > 隐私”中勾选后才会记录。

| 档位 | 选项 | 配置项（`%USERPROFILE%\zhiyi\default.json`） |
|---|---|---|
| 第一档 | 加入用户体验改进计划 | `privacy.experience_program` |
| 第二档 | 允许收集您的输入信息 | `privacy.collect_input` |

- 第二档需要第一档：勾选第二档时会先确认，并同时勾选第一档；取消第一档时第二档也会取消。
- **所有记录只保存在你的电脑上，不会自动上传。** 只有你自己把文件发给别人（例如用
  `collect_diagnostics.ps1 -IncludeLogs` 打包后发给开发者）时，别人才能看到。
- 取消勾选后立即停止记录，已有的记录会保留；“设置 > 隐私”中的“删除所有记录”会一次删除两档的全部记录。
- 记录由后台服务 `zhiyi-server.exe` 写入，实现见 `engine/src/experience_log.cc`。

## 第一档：基本信息

文件：`%USERPROFILE%\zhiyi\logs\experience.jsonl`，每行一条 JSON 记录；超过 1 MB 时改名为
`experience.1.jsonl`（只保留这一份旧文件）。每条记录都有 `t`（UTC 时间）和 `event`（记录类型）。

| 记录 | 何时写入 | 内容 |
|---|---|---|
| `start` | 后台服务启动时 | `version` 输入法版本；`windows` Windows 版本号；`cpu_count` CPU 逻辑核数；`memory_gb` 内存大小（GB） |
| `config` | 首次开启和设置改变时 | `settings`：中文输入方式（拼音/五笔）、拼音方案、首字母模式、模糊音开关及组合、自学习、每页候选数、字号、主题、界面语言、推荐模型开关、英文纠错、英文单词模式、渲染方式、横排/竖排、是否允许收集输入信息、更新提醒开关、4 个切换键及轻按 Shift/Ctrl 的设置 |
| `health` | 每 30 分钟检查一次，只在出错或推荐模型状态变化时写入 | `errors` 这段时间无法生成回应的次数（这种情况下按键会漏给程序）；`laya` 推荐模型状态（off / ready / failed） |

第一档**不包含**：任何输入内容、按键、使用的程序、使用量统计。

## 第二档：输入信息

文件：`%USERPROFILE%\zhiyi\logs\input-YYYYMMDD.jsonl`（每天一个文件，日期为 UTC）。只保留最近
7 天，所有文件合计不超过 10 MB，超出时先删除最早的文件。

### `input`：每次输入一条

从输入法开始处理一次输入（例如打下第一个拼音字母）到上屏或取消，写一条记录：

| 字段 | 内容 |
|---|---|
| `t` | 写入时间（UTC） |
| `app` | 正在输入的程序文件名，例如 `WINWORD.EXE` |
| `window_title` | 该程序前台窗口的标题（常包含文档名或网页标题） |
| `mode` | 输入方式：pinyin / wubi / mixed / english / symbol |
| `keys` | 这次输入中输入法处理的按键，例如 `["n", "i", "SPACE"]`（含退格、方向键、翻页、数字选词等） |
| `code` | 输入的编码，例如拼音 `nihao` |
| `candidates` | 上屏前显示的那一页候选词，以及哪个是推荐词 |
| `picked` | 选了第几个候选（从 0 开始；-1 表示不是从候选里选的） |
| `committed` | 上屏的文字（取消时为空） |
| `laya_context` | 交给推荐模型的上文：这次输入开始时光标前的文字（中文最多 128 个字，英文最多 192 个字符）。它从输入框读取，可能包含不是用知意输入法打的字，例如粘贴的内容或输入框里原有的内容；程序不允许读取时，是之前用知意输入法上屏的文字 |
| `duration_ms` | 这次输入用了多少毫秒 |

### `stats`：每 30 分钟一条使用统计

`minutes` 统计时长；`keys` 输入法处理的按键次数；`latency_ms_buckets` 按键处理耗时分布（<5、<10、<20、<50、<100、<200、≥200 毫秒各多少次）；`max_latency_ms` 最长耗时；`picks_by_position` 选第 1～10 个候选各多少次；`picks_with_recommendation` 有推荐词时的选择次数；`recommendation_picked` 其中选了推荐词的次数；`laya_calls`、`laya_reordered`、`laya_last_ms` 推荐模型的调用次数、调整排序次数、最近一次推理耗时。

### 第二档也不记录的内容

- **输入法没有处理的按键**：英文模式下直接交给程序的字母、各种快捷键（如 Ctrl+C）、没有在输入时按下的其他键。
  （这些字如果在光标前，会作为上文出现在 `laya_context` 中。）
- **密码框**：系统会在密码框中停用输入法，这些按键不会到达输入法；输入法也不会读取密码框和其他标为私密的输入框里的文字。
- 用户名、电脑名、IP 地址、硬件序列号等身份信息，以及完整的文件路径。

## 推荐模型读取的上文（与本计划无关）

为了按上下文推荐候选，每次开始输入时，输入法会读取输入框里光标前最多 256 个字，交给本机运行的推荐模型。
这些文字只在内存中使用，**不联网、不写入任何文件**；只有开启了第二档，才会按上表写入 `laya_context`。
密码框和标为私密的输入框不会读取。关闭推荐模型（`laya.enable`）后也不再读取。

## 检查更新（与本计划无关）

“设置 > 更新”中的“有新版本时提醒我”（默认开启，配置项 `update.notify`）会在打开设置时，从
GitHub 下载最新版本的版本信息（`latest.json`）；点击“检查更新”时也会下载。这只是普通的文件下载，
**不发送任何输入法数据或记录**，GitHub 能看到的只有访问者的 IP 地址和程序版本（User-Agent）。
只有点击“立即更新”时才会下载安装包，校验签名和 SHA-256 后再启动安装程序。

“设置 > 学习”的语言包同样如此：打开设置时（开启了上面的提醒）以及点击“检查更新”“全部检查更新”时下载
语言包清单（`glossary.json`），点击“下载”或“更新到 vN”时下载语言包文件，校验签名和 SHA-256 后才使用。
查翻译完全在本机进行，输入的内容不会发出去。

## 备份文件（与本计划无关）

“设置 > 词库”的“导出…”生成的备份文件包含设置、词库和学习记录，也就包含你打过的词；它只写到你选的文件夹，
不会上传。隐私的两档勾选不在备份里，导入别的电脑的备份不会改变这台电脑的选择。

## 开发诊断日志（与本计划无关）

`diagnostics.trace_mode`（默认 `off`）是开发调试用的详细跟踪，开启后会记录输入的编码等内容，写在同一个
`logs` 文件夹的 `*-trace.jsonl` 中。设置界面中没有它的开关，用户体验改进计划也不会开启它。
